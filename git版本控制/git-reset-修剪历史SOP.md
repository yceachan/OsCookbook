### 1. `git reset` 的三种模式对比

| 模式              | HEAD 指针 | 暂存区（Index） | 工作区（Working Directory） | 典型用途                             |
| :---------------- | :-------- | :-------------- | :-------------------------- | :----------------------------------- |
| `--soft`          | 移动      | **不变**        | **不变**                    | 撤销 commit，但保留所有更改在暂存区  |
| `--mixed`（默认） | 移动      | **重置为 HEAD** | **不变**                    | 撤销 commit 和暂存，但保留工作区修改 |
| `--hard`          | 移动      | **重置为 HEAD** | **重置为 HEAD**             | 彻底丢弃所有更改（危险）             |

## 需要整理历史，分批提改动

- 使用 `[--mixed] <commit>` 而非`soft` ,后者不会撤销暂存，不适合重新整理提交
- [optional] 在强制要求clean workspace 的仓库，使用`stash`命令来暂时藏匿工作区改动，辅助提交. [git-stash-Usage.md][./git-stash-Usage.md]
